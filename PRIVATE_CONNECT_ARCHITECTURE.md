# Private Connect: Architecture

## Existing system (inspected 2026-11-27)

- **Frontend:** Next.js 16.2.4 App Router, React 19, Tailwind v4, on Vercel. No auth system, no database.
  Pages: `/`, `/research`, `/publications`, `/tools`, `/tools/prrsloom`, `/blog`, `/about`.
  Shared chrome in `app/layout.tsx` (`SiteHeader`, `Backdrop`, footer). Shared data in `app/_data/profile.ts`.
- **Existing APIs:** Next route handlers `app/api/analyze` (EGStat-N), `app/api/qigenex` and
  `app/api/prrsloom/*` (proxy to backends).
- **Backends:** QI-GeneX-N FastAPI on Oracle (`api.fnunahiduzzaman.com`); PRRSLooM FastAPI on GCP VM
  `instance-20261114-064217` (`prrsloom-api.fnunahiduzzaman.com`, nginx + certbot). Neither is touched.

## Target topology

```
Browser ──HTTPS──> www.fnunahiduzzaman.com (Vercel, Next.js)   pages under /connect/*
   │
   ├─HTTPS / WSS──> connect-api.fnunahiduzzaman.com (new GCP VM, Nginx → Node connect-backend :8020)
   │                    ├─ PostgreSQL 16 (durable state)
   │                    ├─ Redis 7 (presence, rate limits, socket adapter, transient state)
   │                    └─ GCS private bucket (files, via signed URLs)   [Phase 4]
   └─WebRTC─────> connect-media.fnunahiduzzaman.com (LiveKit SFU + TURN)   [Phase 5]
```

The Next.js app only renders UI. Every authorization decision is made in `connect-backend`.

  db/schema.ts         Drizzle tables

## Data model (Phase 2 tables; later phases add their own)

| Table | Key columns | Notes |
|---|---|---|
| `users` | id uuid, username citext unique, email citext unique, full_name, bio, avatar_key, password_hash, role (`admin`/`member`), status (`pending_verification`/`pending`/`active`/`rejected`/`suspended`/`banned`), email_verified_at, terms_accepted_at, mfa_enabled, totp_secret (encrypted), created_at | role is never taken from client input |
| `sessions` | id, user_id FK cascade, token_hash unique, created_at, last_seen_at, expires_at, revoked_at, ip, user_agent, mfa_passed | 12 h idle / 7 d absolute |
| `one_time_tokens` | id, user_id FK cascade, purpose (`verify_email`/`reset_password`/`mfa_pending`), token_hash unique, expires_at, used_at | single use, hashed |
| `recovery_codes` | id, user_id FK cascade, code_hash, used_at | Argon2id hashes |
| `app_settings` | key text pk, value jsonb | `registration_enabled`, `require_approval` (default true), `maintenance_mode` |
| `audit_logs` | id, actor_id, action, target_type, target_id, metadata jsonb, created_at | no secrets, no message content |
| `security_events` | id, user_id null, kind, ip, metadata, created_at | failed logins, lockouts, MFA failures |

TOTP secrets are encrypted with AES-256-GCM using `CONNECT_DATA_KEY` (32 bytes from secret manager).

## API (Phase 2)

All under `/api/v1`. JSON only. State-changing requests require `X-Connect-CSRF: 1` and an allowed `Origin`.

| Method & path | Auth | Purpose |
|---|---|---|
| GET `/health` | none | `{status:"ok"}` only |
| POST `/auth/register` | none | create `pending_verification` member, send verify mail; always 202 |
| POST `/auth/verify-email` | none | token → status `pending` (or `active` if approval off); notify admins |
| POST `/auth/login/member` | none | username/email + password; members only |
| POST `/auth/login/admin` | none | admin only; returns `mfa_required` step |
| POST `/auth/mfa/verify` | mfa-pending token | TOTP or recovery code → full session |
| POST `/auth/logout` | session | revoke current session |
| GET `/auth/me` | session | current user |
| GET/DELETE `/auth/sessions[/:id]` | session | list / revoke own sessions |
| POST `/auth/password/change` | session | re-auth with current password; revokes other sessions |
| POST `/auth/password/forgot` | none | always 202; sends reset mail if account exists |
| POST `/auth/password/reset` | none | token + new password; revokes all sessions |
| POST `/auth/mfa/enroll` + `/auth/mfa/enroll/confirm` | admin session | TOTP setup, returns recovery codes once |
| GET `/admin/users?status=` | admin+MFA | list |
| POST `/admin/users/:id/{approve,reject,suspend,ban,reactivate}` | admin+MFA | status transitions; revoke sessions on suspend/ban |
| POST `/admin/users/:id/role` | admin+MFA | promote/demote; refuses to remove last active admin |
| GET/PUT `/admin/settings` | admin+MFA | registration + approval toggles |
| GET `/admin/audit` | admin+MFA | audit log page |

## Real-time (Phase 3 outline)

Socket.IO on the same service, authenticated from the session cookie during the handshake;
every event authorized again server-side; Redis adapter for multi-instance; rooms per channel and
per private conversation; server-authoritative dashboard state with monotonically increasing
`version`, client acks with event ids for de-duplication, and snapshot recovery on reconnect.
